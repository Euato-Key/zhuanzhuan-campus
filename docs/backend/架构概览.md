# 后端架构

## 技术栈

- Node.js + Express + TypeScript
- Prisma ORM（MySQL）
- JWT（jsonwebtoken）+ bcryptjs
- Nodemailer（QQ 邮箱 SMTP）
- Socket.io
- Ali-OSS（阿里云对象存储）

## 模块分层

每个业务模块遵循三层结构：

| 层级         | 文件                | 职责                           |
| ------------ | ------------------- | ------------------------------ |
| Routes       | `*.routes.ts`       | 路由定义，中间件绑定           |
| Controller   | `*.controller.ts`   | 参数校验，调用 Service，返回响应|
| Service      | `*.service.ts`      | 业务逻辑，数据库操作           |

## 模块列表

## 统一响应格式

```typescript
// 成功
{ code: 200, data: T, message: "success" }

// 失败
{ code: 400, data: null, message: "错误描述" }
```

通过 `utils/response.ts` 的 `success()` 和 `fail()` 函数统一处理。

**自动序列化**：response.ts 会自动处理 BigInt、Decimal、Date 类型的序列化，避免 JSON.stringify 报错。

## 鉴权中间件

### authMiddleware

从 `Authorization: Bearer <token>` 提取并验证 JWT，将解码后的 `{ userId, role }` 挂载到 `req.user`。

### adminMiddleware

验证 `req.user.role` 是否为 `admin` 或 `super_admin`。

### superAdminMiddleware

验证 `req.user.role` 是否为 `super_admin`。

## 环境变量

通过 `config/env.ts` 统一读取，所有环境变量通过 `env.xxx` 访问，不在业务代码中直接读取 `process.env`。

**启动验证**：必需的环境变量（DATABASE_URL、JWT_ACCESS_SECRET、JWT_REFRESH_SECRET）在启动时会自动检查，缺失时会抛出错误。

关键变量：

| 变量名                | 说明                  | 必需 |
| --------------------- | --------------------- | ---- |
| PORT                  | 服务端口（默认 3000） | 否   |
| DATABASE_URL          | MySQL 连接字符串      | 是   |
| JWT_ACCESS_SECRET     | Access Token 密钥     | 是   |
| JWT_REFRESH_SECRET    | Refresh Token 密钥    | 是   |
| QQ_EMAIL              | QQ 邮箱地址           | 否   |
| SMTP_AUTH_CODE        | QQ 邮箱授权码         | 否   |
| CLIENT_ORIGIN         | 前端地址（CORS）      | 否   |
| OSS_REGION            | OSS 区域              | 否   |
| OSS_BUCKET            | OSS 存储桶            | 否   |
| OSS_ACCESS_KEY_ID     | OSS Access Key        | 否   |
| OSS_ACCESS_KEY_SECRET | OSS Secret            | 否   |
| OSS_ROLE_ARN          | OSS STS 角色 ARN      | 否   |


## 安全注意事项

1. **验证码生成**：使用 `crypto.randomInt()` 而非 `Math.random()`，防止预测攻击
2. **验证码比较**：使用 `crypto.timingSafeEqual()` 防止时序攻击
3. **JWT 密钥**：启动时检查密钥长度，建议至少 32 字符
4. **密码存储**：使用 bcrypt 哈希，盐值轮数 10
5. **Refresh Token**：存储哈希值而非明文，支持吊销机制
6. **参数验证**：使用 ValidationUtil 统一验证，避免遗漏
7. **数据清理**：定时清理过期的 token 和验证码，减少数据库膨胀
