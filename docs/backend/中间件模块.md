# 中间件模块

## 概述

中间件模块 (`backend/src/middlewares/`) 提供了请求拦截和权限验证功能，用于保护需要认证或特定权限的 API 端点。

## 模块列表

| 文件 | 说明 |
|------|------|
| auth.ts | JWT 鉴权中间件 |
| admin.ts | 管理员权限中间件 |

---

## auth.ts - JWT 鉴权中间件

### 功能

从请求头中提取并验证 JWT Access Token，将解码后的用户信息挂载到 `req.user`。

### 使用方式

```typescript
import { authMiddleware } from '../middlewares/auth';

// 保护需要登录的路由
router.get('/profile', authMiddleware, controller.getProfile);
```

### 工作流程

1. 检查 `Authorization` 请求头是否存在且以 `Bearer ` 开头
2. 提取 Token（去掉 `Bearer ` 前缀）
3. 使用 `jwt.verify()` 验证 Token 签名和有效期
4. 将解码后的 `{ userId, role }` 挂载到 `req.user`
5. 调用 `next()` 继续后续处理

### 错误响应

| 场景 | HTTP 状态码 | 消息 |
|------|-------------|------|
| 缺少 Authorization 头 | 401 | 未登录 |
| Token 格式错误 | 401 | 未登录 |
| Token 过期或无效 | 401 | 登录已过期，请重新登录 |

### JwtPayload 类型

```typescript
interface JwtPayload {
  userId: number;
  role: string;  // 'user' | 'admin' | 'super_admin'
}
```

通过 TypeScript 类型扩展，`req.user` 在后续处理中可直接访问：

```typescript
declare global {
  namespace Express {
    interface Request {
      user?: JwtPayload;
    }
  }
}
```

## admin.ts - 管理员权限中间件

### 功能

验证用户角色是否满足指定的权限要求，用于保护管理员专属的 API 端点。

### 使用方式

```typescript
import { authMiddleware } from '../middlewares/auth';
import { adminMiddleware, superAdminMiddleware } from '../middlewares/admin';

// 需要普通管理员权限
router.get('/admin/products', authMiddleware, adminMiddleware, controller.getAdminList);

// 需要超级管理员权限
router.post('/admin/users/:id/ban', authMiddleware, superAdminMiddleware, controller.banUser);
```

### 可用中间件

| 中间件 | 允许的角色 | 说明 |
|--------|-----------|------|
| `adminMiddleware` | admin, super_admin | 普通管理员权限 |
| `superAdminMiddleware` | super_admin | 超级管理员权限 |

### 工作流程

1. 检查 `req.user` 是否存在（需要先经过 `authMiddleware`）
2. 检查用户角色是否在允许的角色列表中
3. 不满足条件时抛出 `forbidden` 错误

### 错误响应

| 场景 | HTTP 状态码 | 消息 |
|------|-------------|------|
| 未登录（req.user 不存在） | 401 | 未登录 |
| 权限不足 | 403 | 无权限访问 / 需要超级管理员权限 |

### 实现模式

使用工厂函数 `createRoleMiddleware` 创建角色检查中间件，避免重复代码：

```typescript
function createRoleMiddleware(allowedRoles: UserRole[], errorMessage: string) {
  return (req: Request, res: Response, next: NextFunction) => {
    // ... 检查逻辑
  };
}
```

## 最佳实践

### 中间件顺序

权限中间件必须放在 `authMiddleware` 之后：

```typescript
// ✅ 正确
router.get('/admin/data', authMiddleware, adminMiddleware, controller.getData);

// ❌ 错误 - adminMiddleware 无法获取 req.user
router.get('/admin/data', adminMiddleware, controller.getData);
```

### 在 Controller 中获取用户信息

```typescript
export const SomeController = {
  getProfile: asyncHandler(async (req: Request, res: Response) => {
    const userId = req.user!.userId;  // 非空断言，因为已通过 authMiddleware
    const result = await Service.getProfile(userId);
    return success(res, result);
  }),
};
```

### 使用 ValidationUtil 安全获取用户 ID

```typescript
import { ValidationUtil } from '../common/validation';

export const SomeController = {
  doSomething: asyncHandler(async (req: Request, res: Response) => {
    // 更安全的方式，会自动检查并抛出 unauthorized 错误
    const userId = ValidationUtil.requireUserId(req);
    // ...
  }),
};
```

## 常见问题

### Q: 为什么 Token 验证失败返回 401 而不是 403？

A: 401 表示"未认证"，403 表示"已认证但无权限"。Token 无效或过期属于未认证状态。

### Q: 如何区分普通管理员和超级管理员？

A: 超级管理员拥有最高权限，可以封禁用户、处理举报等；普通管理员只能审核商品。具体权限由业务逻辑决定。

### Q: Token 过期后如何处理？

A: 前端应调用 `/api/auth/refresh-token` 使用 Refresh Token 获取新的 Access Token。如果 Refresh Token 也过期，用户需要重新登录。
